発表者とチャットで話しながらデッキを作ります。最初に `AGENTS.md` と `design-system/project/README.md` を読み、デザインと言葉のルールはそれに従います。

話の中身は発表者の中にあるので、決まっていないことは質問します。質問は1回に1つにして、すぐ答えられる聞き方にします。素材や話から分かることは聞き直しません。

## 手順

0. **テーマを決める。** LT なら `iotlt`、講演や研修なら `lecture` です（`AGENTS.md` の「テーマを選ぶ」）。分からなければ最初に聞きます。`lecture` のときは、以下の README と書き方を `design-system/lecture/` の文書に読み替え、書き終えたら `npm run check` を通します。
1. **何の話かを聞く。** `inbox/` を一覧します（`_used/` は処理済みなので除きます）。素材があれば中身を見てから、なければそのまま、今回の話を聞きます。`inbox/` が空でも始められます。発表者の言葉がそのままスライドの材料になります。
2. **デッキを用意する。** 日付、イベント、短い英語名が分かったら取り込みます。あとから素材が足されたら、同じコマンドをもう一度実行します。

   ```bash
   node scripts/new-deck.mjs <YYYYMMDD_name> --title "仮のタイトル"
   ```

   注意が表示されたら発表者に伝えます。
3. **素材をすべて見る。** `images.md` の画像を1枚ずつ開き、`notes/` を読みます。ファイル名だけで判断すると、写っていないことを書いてしまいます。
4. **構成を相談する。** 1枚1行の見出しをチャットに書き、README の「デッキの構成」に当てはめます。話の順番や足りないところを発表者と決めてから書き始めます。
5. **デッキを書く。** `deck.md` を `design-system/project/marp.md` の書き方で書きます。1つのファイルからスライド、記事、PDF ができるので、話す内容は発表者ノート（`<!-- -->`）に書きます。
   - 発表者が言ったこと、写っていて確かなことだけを書きます。
   - 推測した動機、結果、感想、数値は書きません。発表者に聞き、その場で分からなければ「【要確認】」を付けます。発表者が試していないことがスライドに残るのがいちばん困ります。
   - 足りない素材は `lt-slot` にして、何を撮れば良いかを具体的に伝えます。
6. **書き出して目で確かめる。**

   ```bash
   scripts/export-pdf.sh decks/<デッキ名>
   ```

   `deck.html?overview` か PDF で全ページを見て、文字のはみ出し、タイトルの折り返し、画像との重なりを直します。
7. **見せて直す。** デッキと PDF のパス、残っている「【要確認】」と `lt-slot`、使わなかった画像を伝え、発表者の感想を聞いて直します。

公開とコミットは、発表者が頼むまでしません。頼まれたら `AGENTS.md` の「公開する」に従います。
