IoTLT などのライトニングトーク用スライドを、AI が HTML で組み立てるためのルール集です。1920×1080 の白地に、グレーのゴシックと実物の写真・スクショだけで構成します。飾りは足しません。

## スライドの作り方

1. `tokens.css`、`components/bundle.css`、`components/bundle.js` を読み込み、`<main class="lt-deck">` の中に `<section class="lt-slide">` を並べ、最後に `IoTLT.Deck.mount()` を呼びます。
2. 1枚ごとに下のコンポーネントを1つ選び、その README の HTML をそのまま使います。CSS は新しく書きません。
3. 手元にない写真・スクショ・デモ結果は `lt-slot` にし、何を入れるかを日本語で書きます。

```html
<main class="lt-deck">
  <section class="lt-slide">
    <h1 class="lt-title">反応をみる MQTTも</h1>
    <div class="lt-stage">
      <ul class="lt-bullets lt-body"><li>思ったよりいい感じに反応してくれた</li></ul>
    </div>
  </section>
</main>
```

## 内容の原則

**口調。** 日本語の話し言葉で、短く書きます。「やってみた」「使えそう」「むずい」「つまらん」のように、発表者がそのまま口に出す言葉を使います。かしこまった言い回し（「本スライドでは」「〜を実現します」）は使いません。

**タイトルは文にします。** 項目名ではなく、その1枚で起きたことを書きます。

| 使う（実際のスライドより） | 使わない |
| --- | --- |
| 初っ端から起動がうまくいかず苦戦 | 課題 |
| 制限きてしんだ。（明日の午前7時に試せるらしい） | 今後の予定 |
| SenseCraft AIのWeb画面にアップロードするだけ | モデル作成手順 |

**決まった言い回し。**

- `=>` で「つまり」「だから」を示します。例：`=> 今日はBBQなので焼肉判定モデル作ってみよう`
- `蛇足:` は本筋から外れた小話のタイトルに付けます。
- `STEP1` `STEP2` は手順が3つ以上あるときの番号に使います。
- `（謎）` や `（コゲ画像以外と少ない）` のような丸括弧のひとことで、話し手のツッコミを入れます。
- 出典は `引用元:` または `参考:` に URL を続け、人の写真には `（@youtoy さん撮影 URL）` のように撮影者を書きます。

**失敗も話のうちです。** うまくいかなかったことは、そのまま1枚にします。結果を盛らず、良い結末を作りません。未検証なら「検証途中」と書きます。

**絵文字は基本的に使いません。** 例外は、正誤の例を示す ❌ と 🙆 だけです。

**AI が守ること。** 発表者が実際に試していない結果、数値、デモ、感想を書きません。分からない箇所は `lt-slot` か「【要確認】」と書き、下書きとして渡します。実在の写真の代わりに生成画像を入れるのは、発表者が頼んだときだけです。

## デッキの構成

原本の4本（13〜32枚）はどれも次の順で進みます。1枚に1つの話だけを載せるので、5分でも20枚前後になります。

1. **TitleSlide**：タイトル、著者、日付とハッシュタグ。
2. **Profile**：毎回同じ自己紹介に、最近のネタを1行足します。
3. **つかみ**：Statement を1〜3枚。イベントや季節の話から入ります（「本日はBBQですね」「AI時代ですね」）。
4. **作りたいもの**：なぜやるのかを1枚で。（「タイムラプス撮りたい」）
5. **技術の紹介**：MediaSplit で、製品やサービスのスクショと箇条書き。
6. **やってみた**：CodeBlock、Diagram、Screenshot、Collage で手順と苦戦を順に。
7. **DEMO**：Demo か FullPhoto で実物を。
8. **Summary**：最後は必ず `まとめ`。最後の項目に今後のひとことを置くこともあります（「またさわろう。」）。

**段階的に見せるときは、スライドを複製します。** 同じ1枚をコピーして要素を1つ足します（`lt-red` のオチを足す、スクショを重ねるなど）。アニメーションは使いません。

## ビジュアルの基礎

**色。** 背景は常に `paper`、文字は `ink` です。無彩色が基本で、色は写真とスクショが持ち込みます。テーマは白の1種類だけで、ダークテーマは作りません。

- `ink-strong`：Profile の名前、強調語、URL、図の線。
- `accent-red`（`.lt-red`）：1枚に1か所のオチだけに使います。
- `mark-red`（`.lt-mark`、`.lt-markline`）：スクショの注目箇所を囲む・下線を引く専用です。
- `logo-teal`：アバターの中にだけ現れます。見出しや図には使いません。

**文字。** タイトルは `lt-title`（54px）、入りきらなければ `lt-title-sm`（47px）。本文は `lt-body`（47px）、画像と並べるなら `lt-body-sm`（40px）。出典は `lt-caption`（33px）です。太字は Yu Gothic Bold、本文は Medium、コードは Menlo で、字間は -0.02em、行の高さは 1.3 です。大事な語句は `<b>` で太くし、さらに強めるときだけ `.lt-strong` で黒にします。Yu Gothic がない環境では Noto Sans JP で表示されます。

**配置。** タイトルは上部中央に置き、本文は残りの領域の中央に置きます。Lines と Bullets の中身は左揃えです。グリッドにきっちり揃えず、話の流れに合わせて大きさを変えて構いません。

**画像。** 写真とスクショは角丸・影・枠なしで、白地にそのまま置きます。重ねて構いません（Collage）。

**線と形。** 図は `stroke-rule`（2px）の黒い矢印と囲み枠、`stroke-mark` のクラウド図形で描きます。角丸は `radius-none` が基本です。影はアバターの `shadow-avatar` だけです。

**動き。** 使いません。ページ送りだけです。

## ロゴとアイコン

- 著者アイコンは `assets/Logos/nobisuke-avatar.jpg` を `lt-avatar` で丸く抜いて使います。再描画や色の変更はしません。
- アイコンセットはありません。製品ロゴや機器の写真は、その製品の実物の画像を `lt-slot` に差し込みます。ロゴを AI が描き起こすことはしません。
- 矢印は `=>` と `↓` の文字、または `lt-arrow` です。

## 書き出し

`.lt-slide` は印刷時に1枚1ページ、1920×1080 になります。ブラウザの印刷か headless Chrome の `--print-to-pdf` で PDF にします。

## 使わないもの

- 色付きの背景、グラデーション、カード、影付きのパネル
- 飾りのアイコンや絵文字の見出し
- 「目次」「背景」「課題」「結論」のような項目名だけのタイトル
- 1枚に2つ以上の話
