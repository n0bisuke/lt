# 今日のメッセージ

**作って試す人を増やそう。**

設計の工夫も発信して、仲間と学び続けよう。

<!-- 今日の話は、作るのを止めるためのセキュリティではありません。作って試す人を増やすために、使う側、作る側、管理する側にできることを考えます。 -->

---

# 作る人だけに背負わせない

- 使う人 => 渡す情報を選ぶ
- 作る人 => 集める情報と保存先を考える
- 管理する人 => 安全に試せる場を作る

<!-- 今日は3つの立場から考えます。使う人が気をつけるだけでも、作る人が頑張るだけでもなく、管理する人も含めて試せる環境を作ることが大事です。 -->

---

# 使うときは、必要以上に情報を渡さない

- AIやサービスに患者さんの実データを入れない
- 任意の項目は、必要なければ埋めない
- メールは用途別アドレスやエイリアスも使う

<!-- 利用者としては、入力する情報を一度立ち止まって見ます。試作中のAIに患者さんの実データを入れず、ダミーデータにする。任意項目は必要がなければ入力しない。メールアドレスは用途別やエイリアスを使えることもあります。住所など必須の欄に適当な値を入れるのではなく、サービスに本当に必要かを確認します。 -->

---

# 試作は、まずダミーデータで動かす

- 氏名 => 患者A
- 生年月日 => 仮の日付
- 問診内容 => テスト用の例

<!-- 作る人は、最初から実際の患者さんのデータを使わないで、ダミーデータで画面や処理を試せます。実際の情報が必要になる段階が来たら、目的や扱いを確認してから進みます。 -->

---

# AIが作ったフォームを、そのまま使わない

- その情報は何のため？
- 必須にする理由はある？
- 保存する必要はある？

<!-- AIにフォームを作らせると、よくある入力欄が一式ついてくることがあります。名前や生年月日を入れる前に、何に使うのか、必須なのか、保存するのかを考えます。 -->

---

# フォームは、必要な項目だけにする

- 入力が減る => 患者さんの手間が減る
- 持つ情報が減る => 守る情報も減る

<!-- 「フォームを作るな」ではなく、必要な項目だけのフォームにします。入力の負担や入力ミスが減り、作った側が守るデータも少なくできます。 -->

---

# 保存する情報と期間を決めておく

- そもそも保存しない
- 必要な期間が過ぎたら消す
- 便利だから、で残し続けない

<!-- データは、集めた時点だけでなく保存中も守らなければいけません。使う目的が終わったら削除できるか、最初に考えておくと運用も楽になります。タイムズカーの事例も、情報を持つ期間を見直すきっかけとして紹介しました。 -->

---

# アプリには、必要な情報だけ見せる

- 患者情報と問診内容を分けて考える
- アプリごとに必要なデータだけ使わせる
- 分離は、できる範囲から

<!-- DBを分けるという方法もあります。ただ、分ければそれだけで安全になるわけではありません。まずはアプリが必要以上の情報にアクセスしないようにする、という設計の考え方を持ち帰ってください。 -->

---

# AIへの指示に、データの条件も書く

- 目的に必要な入力項目だけにする
- 実データを使わず、ダミーデータで試す
- 保存する情報と削除方法も説明させる

<!-- アプリをAIに作ってもらうときは、画面や機能だけでなく、データの条件も指示に書きます。たとえば「入力項目は目的に必要なものだけ。テストにはダミーデータを使う。保存する情報と削除方法を説明して」といった形です。これは一つの指示例で、出力された設計を人が確認します。 -->

---

# 管理する人は、安全に試せる場を作る

- ダミーデータを使える
- 公開範囲を限定できる
- 本番のシステムや患者情報から切り離す

<!-- 管理者や組織には、禁止だけでなく、試作できる環境を用意する役割があります。ダミーデータで、公開範囲を限定して、本番環境から切り離して試せる場所があると、作る経験を安全に積みやすくなります。 -->

---

# 紙でも、情報は漏れる

- 紙をなくす
- 置き忘れる
- 見られる

<!-- 漏えいの原因はアプリだけではありません。紙の名簿や問診票も、なくしたり、置き忘れたり、第三者に見られたりします。道具を変えるだけで安全になるわけではなく、扱う人が仕組みを理解することが大事です。 -->

---

# だから、結局は教育です

- 作ってみる
- どこに情報があるか考える
- 失敗や工夫を共有する

<!-- これは僕の感覚ですが、ある程度安全な環境で実際にシステムを作ってみることが大切です。作る経験があると、データがどこに行くのか、誰が使えるのかを具体的に考えられるようになります。 -->

---

# 情報もサービスも、変わっていく

- AIサービスの契約や設定
- アプリの機能や公開方法
- 新しい脆弱性や事故事例

<!-- 今日話したことも、AIサービスやアプリの仕組みが変われば見直しが必要です。一度覚えたルールだけで終わらず、仲間と情報を更新していきます。 -->

---

# 設計の工夫を、作った人から発信しよう

- 何を作った？
- どんな情報を集めないと決めた？
- どこまで試して、次に何を確認する？

<!-- 動くものだけでなく、どう設計したか、何を集めないと決めたか、まだ何を確認中かも発信すると、次に作る人の参考になります。自信を持って「ここは意識してます」と言えることを増やしていきましょう。 -->

---

# ひとりで抱えず、コミュニティで学ぼう

- もいせん
- プロトアウトスタジオ
- 医療者・開発者のコミュニティ

<!-- 作る経験やセキュリティの知識を、ひとりで抱え込まない。もいせんやプロトアウトスタジオ、医療者や開発者のコミュニティに参加して、作ったものや設計の工夫を見せ合いながら学び続けることにつなげたいです。 -->
