発表者とチャットで話しながらデッキを作ります。最初に `AGENTS.md` と `design-system/project/README.md` を読み、デザインと言葉のルールはそれに従います。

話の中身は発表者の中にあるので、決まっていないことは質問します。質問は1回に1つにして、すぐ答えられる聞き方にします。素材や話から分かることは聞き直しません。

## 手順

0. **テーマを決める。** LT なら `iotlt`、講演や研修なら `lecture` です（`AGENTS.md` の「テーマを選ぶ」）。分からなければ最初に聞きます。`lecture` のときは、以下の README と書き方を `design-system/lecture/` の文書に読み替え、書き終えたら `npm run check` を通します。
1. **何の話かを聞く。** `inbox/` を一覧します（`_used/` は処理済みなので除きます）。素材があれば中身を見てから、なければそのまま、今回の話を聞きます。`inbox/` が空でも始められます。発表者の言葉がそのままスライドの材料になります。
2. **デッキを用意する。** 日付、イベント、短い英語名が分かったら取り込みます。あとから素材が足されたら、同じコマンドをもう一度実行します。

   ```bash
   node scripts/new-deck.mjs <YYYYMMDD_name> --title "仮のタイトル"
   ```

   注意が表示されたら発表者に伝えます。
3. **素材をすべて見る。** `images.md` の画像を1枚ずつ開き、`notes/` を読みます。ファイル名だけで判断すると、写っていないことを書いてしまいます。
4. **構成を相談する。** 1枚1行の見出しをチャットに書き、README の「デッキの構成」に当てはめます。話の順番や足りないところを発表者と決めてから書き始めます。
5. **デッキを書く。** `deck.md` を `design-system/project/marp.md` の書き方で書きます。1つのファイルからスライド、記事、PDF ができるので、話す内容は発表者ノート（`<!-- -->`）に書きます。
   - 発表者が言ったこと、写っていて確かなことだけを書きます。
   - 推測した動機、結果、感想、数値は書きません。発表者に聞き、その場で分からなければ「【要確認】」を付けます。発表者が試していないことがスライドに残るのがいちばん困ります。
   - 足りない素材は `lt-slot` にして、何を撮れば良いかを具体的に伝えます。
   - Web記事や発表資料を事例として見せるときは、文章だけのカードで済ませず、画面そのものが理解の助けになるか確認します。役立つ場合は「スクリーンショットカード」の手順に沿って実際の出典ページを撮影します。
6. **ローカルプレビューで目視する。** `npm run deck -- decks` を起動し、Codexの組み込みブラウザーで確認します。ホストのBraveやChromeは使わず、ローカルではPDFを書き出しません。文字のはみ出し、タイトルの折り返し、画像との重なりを直します。
7. **見せて直す。** デッキのパス、残っている「【要確認】」と `lt-slot`、使わなかった画像を伝え、発表者の感想を聞いて直します。PDFはpush後にGitHub Actionsが生成します。

公開とコミットは、発表者が頼むまでしません。頼まれたら `AGENTS.md` の「公開する」に従います。

## スクリーンショットカード

ニュース、公式発表、投稿、製品画面など、元ページの見た目が話の理解を助ける場合は、出典ページのスクリーンショットをカードに添えます。文字だけの要約カードが広い余白に小さく残る場合も、画像を添える価値を検討します。

1. URLを開き、**Codexの組み込みブラウザー**で実際の公開ページを表示します。ホストマシンのBraveやChromeは使いません。
2. ページ名、発信元、日付、カードに見せたい本文や図表が同じ画面に入る位置に調整します。必要な範囲だけを撮り、余計なブラウザーUIや関係のない情報を含めません。
3. 実際に表示されているページをスクリーンショットとして保存し、`decks/<デッキ名>/images/cards/` に内容が分かるファイル名で置きます。OG画像やAI生成画像を、ページのスクリーンショットとして扱いません。
4. `source-cards` のカードにスクリーンショットを配置し、見出し・短い要約・発信元・日付・元ページへのリンクも残します。画像だけを出典表示の代わりにしません。
   - カード画像と見出しは同じ記事・ページに対応させます。記事カードを別ページのスクリーンショットや画像だけで置き換えず、画像を用意できない場合は元記事の見出しとリンクが分かるカードにします。
5. 画像の文字が読める大きさか、カードの余白が過剰でないか、スライド上で確認します。読めない画像は無理に使わず、要約カードに戻します。

スクリーンショットを取得・保存する機能が使えない場合は、撮影できたふりをしません。URLカードか要約カードを使い、必要なら発表者にページ画像の提供を頼みます。
